# Self-Improvement Session — Coordinator Notes

This example uses the `self-improvement` profile to review `council.md` itself.

## Session setup summary

- **Area under review:** project framing, protocol boundaries, and improvement process
- **Core question:** should the repo keep leading with runtime-free, or reframe itself as file-first, invariant-first, runtime-optional?
- **Blind round:** enabled
- **Session mode:** council

## Why this example exists

The point of this session is to show that `council.md` can:

- critique its own protocol
- preserve disagreement instead of self-validating
- translate criticism into concrete repo changes
- record the outcome in improvement history

## Roster

- **Protocol Defender** — protects load-bearing invariants
- **Protocol Challenger** — makes the strongest critique of the current direction
- **User Reality Critic** — judges whether real users would do this twice
- **Epistemics Auditor** — checks independence, disagreement quality, and synthesis collapse
- **Maintainer** — converts findings into concrete repo changes
- **Historian** — records what changed and whether this is a clarification or a shift
